# Использование AI

Я сформулировала требования и выбрала архитектуру: React + Vite и Supabase без отдельного backend. Codex использовался для AI-assisted разработки: реализации интерфейса, подготовки SQL с RLS, исправлений и технических материалов. Я регистрировала тестовые аккаунты, подключала доступы и участвовала в проверке результата. Технические проверки интерфейса и прямых запросов к Supabase выполнялись с помощью Codex.

## Результат

Подготовлены интерфейс, миграция, автоматические проверки логики поиска/фильтра и сценарии проверки RLS двумя пользователями. Три автоматические проверки прошли, production-сборка завершилась успешно. Миграция выполнена в существующем проекте LD LATTE. Подключение к Supabase работает; анонимный запрос к таблице получает отказ в доступе.

В браузере проверены создание, редактирование названия, описания и категории, смена статусов, сохранение после обновления страницы, поиск и каждый статус в фильтре, их совместная работа. Двойное нажатие «Сохранить» создало одну запись. При ширине окна 360 CSS-пикселей проверены список, создание и редактирование: горизонтальной прокрутки нет.

В опубликованной версии проверены вход B, отсутствие заявок A в его списке, создание собственной заявки B и сохранение после обновления страницы. Ошибка входа отображается понятно. На отдельной локальной странице проверена настоящая форма с контролируемой ошибкой сетевого адаптера: двойной клик отправил один запрос, после ошибки текст остался, кнопка стала доступной, повторная попытка сохранила одну запись.

Прямая проверка RLS прошла: B не получает и не изменяет заявку A, не может создать запись от имени A или передать владельца при обновлении. Начальный статус закреплён, недопустимая категория отклоняется. После повторного входа A видит исходную заявку; все проверенные поля сохранились. Исходники и инструкции загружены в отдельный GitHub-репозиторий.

После подключения существующего проекта Supabase создание и редактирование заявок заработали без изменения архитектуры. Проверки и порядок демонстрации перечислены в `demo-checklist.md`, известные ограничения — в `known-limitations.md`.

## Возникшие проблемы

- Подключённый инструмент GitHub не поддерживал создание репозитория: отдельный репозиторий создан через интерфейс GitHub.
- После создания инструмент не получил право записи в новый репозиторий. В настройках существующей интеграции отдельно разрешён доступ к репозиторию задачи 3, после чего исходники загружены подключённым инструментом.
- Установка зависимостей в ограниченной среде не смогла обратиться к npm. Повторная установка с доступом к сети выполнена; разрешена стандартная сборка esbuild в настройках pnpm.

Для прямой проверки RLS подготовлена локальная страница с обычным клиентом Supabase. Она использует текущую сессию, поэтому пароли не пришлось передавать в чат или сохранять в тестах. Ошибка сетевого адаптера моделировалась отдельно; физическое отключение сети в рабочем проекте не выполнялось.
