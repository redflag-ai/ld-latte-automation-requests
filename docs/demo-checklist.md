# Демонстрация задачи 3

Сценарии ниже проверены при подготовке решения. Для демонстрации можно повторить их с двумя тестовыми аккаунтами.

- [x] Зарегистрировать A, подтвердить email, если это включено в Supabase.
- [x] Войти A, выйти, повторно войти.
- [x] Создать заявку с заполненными обязательными полями. Статус — «Новая».
- [x] Проверить название, категорию, дату и статус в списке.
- [x] Открыть заявку, изменить название, описание и категорию, сохранить.
- [x] Перевести в «В работе», затем «Завершена», проверить сохранение каждого статуса.
- [x] Обновить страницу, затем выйти и войти: данные сохранились.
- [x] Найти заявку по части названия; проверить регистр и отсутствие результатов.
- [x] Проверить каждый статус в фильтре, затем совместно с поиском.
- [x] Быстро дважды нажать «Сохранить»: появилась ровно одна запись.
- [x] Проверить ошибку сохранения и повтор: на локальной странице `/tests/save-browser.html` используется настоящая форма с контролируемой ошибкой сетевого адаптера. Текст сохраняется, кнопка доступна, повтор успешен. Физическое отключение сети не выполнялось.
- [x] Зарегистрировать B, войти B: заявки A не видны.
- [x] Обычным клиентом B запросить ID заявки A: запись не возвращается.
- [x] Обычным клиентом B попробовать изменить заявку A: запись не меняется.
- [x] Проверить запрет создания заявки от имени A через клиент B.
- [x] Снова войти A: заявка доступна и не изменена пользователем B.
- [x] На экране 360 px проверить вход, список, создание и редактирование без горизонтальной прокрутки.

Для отчёта достаточно показать главные состояния интерфейса и приложить результат прямой проверки RLS. Скриншоты не должны содержать пароли, access tokens или приватные ключи.
