# Демонстрация задачи 3

Пункты отмечаются только после фактической проверки в подключённом приложении.

- [ ] Зарегистрировать A, подтвердить email, если это включено в Supabase.
- [ ] Войти A, выйти, повторно войти.
- [ ] Создать заявку с заполненными обязательными полями. Статус — «Новая».
- [ ] Проверить название, категорию, дату и статус в списке.
- [ ] Открыть заявку, изменить название, описание и категорию, сохранить.
- [ ] Перевести в «В работе», затем «Завершена», проверить сохранение каждого статуса.
- [ ] Обновить страницу, затем выйти и войти: данные сохранились.
- [ ] Найти заявку по части названия; проверить регистр и отсутствие результатов.
- [ ] Проверить каждый статус в фильтре, затем совместно с поиском.
- [ ] Быстро дважды нажать «Сохранить»: появилась ровно одна запись.
- [ ] Отключить сеть при сохранении: понятная ошибка, кнопка снова доступна. Вернуть сеть и повторить.
- [ ] Зарегистрировать B, войти B: заявки A не видны.
- [ ] Обычным клиентом B запросить ID заявки A: запись не возвращается.
- [ ] Обычным клиентом B попробовать изменить заявку A: запись не меняется.
- [ ] Проверить запрет создания заявки от имени A через клиент B.
- [ ] Снова войти A: заявка доступна и не изменена пользователем B.
- [ ] На экране 360 px проверить вход, список, создание и редактирование без горизонтальной прокрутки.

Для отчёта достаточно показать главные состояния интерфейса и приложить результат прямой проверки RLS. Скриншоты не должны содержать пароли, access tokens или приватные ключи.
